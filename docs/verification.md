- 先頭・途中・末尾への移動、切り取り／貼り付けのUndo/Redo、保存をまたぐ未保存状態、範囲外の指定を検査しました。保存後のPDFを別途読み直し、ページ数と各ページの原本文字列の順番を照合しています。元ファイルは保存操作までバイト単位で不変です。
- ページを新しいPDFへインポートせず元のカタログ内で参照を移動し、タイトルメタデータ、90度回転、テキスト注釈、しおりの移動先が保持されることを確認しました。PDFsharp 6.2.4ではRemove/Addが参照テーブルの重複例外になるため、公開APIのMovePageを使用します。
- ロックされた保存先では元ファイルと編集状態を保持し、保存用の一時ファイルを残さないことを検査しました。外部で元ファイルが変更された場合は上書きを拒否し、別名保存は成功します。保存先変更後の2回目の保存と、文書管理のパス変更・別ウィンドウとの競合拒否も検査しました。
- パスワード付きPDFと署名欄を含むPDFを拒否し、入力ファイルを変更しないことを検査しました。署名欄の試験は人工の辞書であり、有効な暗号署名を生成・検証する試験ではありません。
- 実際の編集UIのボタンで赤の先頭ページを切り取り、緑の次ページが表示されること、末尾へ貼り付けると赤が表示されること、数字＋Enterで一覧の選択と表示が同期することを中心画素で確認しました。保存先を実際にWebView2で開き直し、先頭は緑、12ページ目は赤と確認しています。

未保存時の保存／破棄／取消ダイアログとSaveFileDialogの対話操作、Explorerからの保存先再オープン、特殊フォーム・PDF/A・PDF/UA・ページラベル等の完全保持、大容量PDFでの操作時間は未確認です。インストーラーの導入・削除試験は既存のSaruPDF登録を保護するため再実行していません。

## 0.2.2：数字＋Enterによるページ移動

2026-10-29、Windows 11 build 26200 / WebView2 Runtime 156.0.4314.50。ビルドは警告・エラー0、通常ユーザー権限で31件すべて成功しました。制限されたサンドボックスではテスト用レジストリへの書き込みとWebView2の読み込みが失敗したため、隔離した同じテストを通常権限で再実行しました。

- 数字キーとテンキーを受け取り、入力中だけ右上に移動先を表示します。Backspaceで修正、Escで取り消し、Enterで確定します。0、空入力、整数の範囲を超える入力を検査しています。
- `AllowHostInputProcessing` を有効にし、PDF本文にフォーカスした実画面で数字キーから一時的な案内が表示されることを確認しました。
- フラグメントだけの変更ではページが移動しなかったため、同じPDFへ一意なクエリー付きで再ナビゲートするように修正しました。12ページの原本PDFをテストコードで生成し、画面外の非アクティブなフォームと独立したWebView2プロファイルで、2→3→12→1ページの実描画の中心画素がそれぞれ緑→青→黄→赤になることを確認しました。Esc取り消しと0入力で赤のままであることも検査しました。URIの文字列だけを成功条件にはしていません。
- 実画面の操作は物理Escで停止されたため、その後は画面操作を再開していません。最終修正後の手動キーボード操作の通し確認は未実施です。既存の検証ウィンドウを残し、インストーラーは別の出力先 `artifacts/package` に生成します。

ページ移動時はPDFを再表示します。ズームなどの状態と総ページ数を超える番号の扱いはWebView2に依存します。インストーラーの導入・削除試験は既存登録を保護するため再実行していません。

## 0.2.1：閉じるボタン・表示・アイコン

2026-10-29、Windows 11 build 26200 / WebView2 Runtime 156.0.4314.50 で確認しました。

- 単独起動は `Application.Run(form)` のため、ボタンの `DialogResult.Cancel` だけでは終了しませんでした。クリックから明示的に `Close()` を呼ぶように修正しました。単独ウィンドウと `ShowDialog()` の双方を実際の WinForms メッセージループで回帰テストしています。タイムアウト時に失敗するため、旧実装のままでは単独起動のテストは通りません。
- 全 `HiddenPdfToolbarItems` の指定だけでは空の帯が残ったため、`UriBuilder` で `toolbar=0` フラグメントも付加しました。実際の PDF 描画画面で、ページ番号等の操作行と空白の帯がなくなり、アクセシビリティツリーにも PDF ツールバーがなくなったことを確認しました。
- タイトルは `論文 A #100% &.pdf（C:\…\論文 A #100% &.pdf）` の形式で、実際の値に省略せず完全パスを設定します。アプリ名の接尾辞はありません。タイトル文字列の自動検査と実画面を確認しました。
- 16 / 20 / 24 / 32 / 40 / 48 / 64 / 128 / 256 px の透過 ICO を生成し、赤い文字の色値と透過領域を自動検査しました。EXE／ウィンドウに組み込み、タイトルバーの赤い PDF 表示を実画面でも確認しました。再生成は `scripts/Generate-Icon.ps1` です。
- 単独起動した関連付け画面の下部「閉じる」を実際にクリックし、右上の × を使わずプロセスが終了することを確認しました。

関連付けの候補登録や既定 PDF アプリは変更せず検証しています。インストーラーの構成は 0.2.0 を継承し、バージョン・アイコン・本体を更新しています。0.2.1 の実環境での導入・削除試験は、既存登録を保護するため実施していません。

## 0.1.0：Windows GUI の再現手順（初版の記録）

`scripts/Test.ps1`、`scripts/Publish.ps1` の実行後、リポジトリ直下の PowerShell から実施します。

```powershell
$exe = (Resolve-Path '.\artifacts\sarupdf-0.1.0-win-x64\sarupdf.exe').Path
$a = (Resolve-Path '.\artifacts\test-data\論文 A #100% &.pdf').Path
$b = (Resolve-Path '.\artifacts\test-data\B.pdf').Path
& $exe $a
& $exe $b
& $exe $a
```

|確認|期待する結果|
|---|---|
|A → B → A の順で追加起動|A と B の独立した 2 ウィンドウ。最後は A がアクティブ|
|A のページを 2、ズームを変更して再度 A を開く|同じウィンドウでページとズームを保持|
|A を最小化して追加起動で A を開く|復元して前面化。最大化から最小化した場合も復元状態を確認|
|A を Ctrl+W で閉じる|B は残り、ページ移動可能|
|B を閉じる|約 200 ms 後に sarupdf プロセスが終了|

|日本語・空白・`#100% &` を含む A を開く|PDF 本文と標準ツールバーが表示される|

|3. A を追加起動で再度開く|成功。同じハンドルの A を前面化し、ウィンドウ数は 2 のまま|
