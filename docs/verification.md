## 0.2.0：名称・インストーラー・関連付け

2026-10-29 にアプリ表示名、EXE、製品メタデータ、セットアップを **SaruPDF** に統一しました。プロジェクトのソースディレクトリ名と初版との互換性が必要な内部 IPC 名は保持しています。

- アプリの「設定 → PDF の関連付け」と `--pdf-association` のダイアログを実際に起動し、SaruPDF の表示名と登録／Windows 設定ボタンを確認しました。画面の確認だけでは登録しません。
- レジストリを使用する 5 件の自動テストはサンドボックスの書き込み制限では実行できなかったため、通常ユーザーの `HKCU\Software\SaruPDF.Tests\<GUID>` 以下に隔離して実行・削除しました。実際の PDF 設定は変更しないテストです。全 22 件成功。
- NSIS は WSL Ubuntu 24.04 の公式パッケージ **3.09-4ubuntu1** を作業フォルダーに展開し、`-WX`（警告をエラーとして扱う）で Windows セットアップ EXE を生成します。
- 初回のインストーラーテストで、NSIS の `GetFullPathName` が存在しない親フォルダーを拒否するため、新規のインストール先が空文字になる問題を検出しました。存在を要求しない Win32 `GetFullPathNameW` に変更し、最小セットアップで新規保存先を確認しました。

セットアップ試験のコマンド：

```powershell
.\scripts\Build-Installer.ps1
.\scripts\Test-Installer.ps1
```

`Test-Installer.ps1` は既存の SaruPDF 登録・ショートカットを見つけた場合は停止します。作業フォルダー内の `artifacts/installer-smoke/インストール 試験 #100% &` だけをテスト先にし、ユーザーの既定 PDF 設定は試験前後で比較します。

|セットアップ試験|結果|
|---|---|
|既存の空フォルダーへ候補登録なしで導入し、削除|成功。関連付けを作らず、配布ファイルを削除|
|新規フォルダーへ候補登録ありで導入|成功。日本語・空白・`#100% &` を含む EXE パスを引用し、Capabilities・OpenWithProgids・スタートメニューを登録。既存の PDF 既定値と UserChoice を保持|
|同じフォルダーに更新し、アンインストール|成功。自分の候補登録とスタートメニューを削除。後から置いた `keep-me.pdf` を保持。既存の PDF 既定値を保持|
|無関係なファイルがある非空フォルダーへ導入を試みる|終了コード 2 で拒否。既存ファイルを保持し、本体を展開しない|

最終ソースのビルドは警告 0・エラー 0、22 件のアプリ自動テストと上記のセットアップ試験 4 項目が成功しました。対話形式のインストールウィザードでの一連のクリック操作は実施していません。

README と検証記録を更新した後の再試験では、配布フォルダーの SaruPDF がすでに PDF 候補として登録されていたため、既存登録を保護するガードで停止しました。その登録は変更していません。本体とセットアップ処理の変更を伴わない文書更新について、登録を上書きしての再試験は行っていません。

Windows の設定画面で実際に既定 PDF アプリを切り替える操作、Windows 10、署名された EXE の受け入れは未確認です。既定変更操作は今回のテストでは行いません。

## 0.1.0：Windows GUI の再現手順（初版の記録）

`scripts/Test.ps1`、`scripts/Publish.ps1` の実行後、リポジトリ直下の PowerShell から実施します。

```powershell
$exe = (Resolve-Path '.\artifacts\sarupdf-0.1.0-win-x64\sarupdf.exe').Path
$a = (Resolve-Path '.\artifacts\test-data\論文 A #100% &.pdf').Path
$b = (Resolve-Path '.\artifacts\test-data\B.pdf').Path
& $exe $a
& $exe $b
& $exe $a
```

|確認|期待する結果|
|---|---|
|A → B → A の順で追加起動|A と B の独立した 2 ウィンドウ。最後は A がアクティブ|
|A のページを 2、ズームを変更して再度 A を開く|同じウィンドウでページとズームを保持|
|A を最小化して追加起動で A を開く|復元して前面化。最大化から最小化した場合も復元状態を確認|
|A を Ctrl+W で閉じる|B は残り、ページ移動可能|
|B を閉じる|約 200 ms 後に sarupdf プロセスが終了|
|同じ A を短時間に 10 回起動|A のウィンドウが 1 つだけ（初期化中も同じ）|
|日本語・空白・`#100% &` を含む A を開く|PDF 本文と標準ツールバーが表示される|
|`別フォルダー` 内の同名 PDF を開く|別ウィンドウになり、パス表示が区別できる|
|存在しない PDF、偽の `text.pdf` を追加起動で指定|既存 PDF は残り、エラーをアプリ内に表示|
|引数なし起動 → Ctrl+O → A を選択|初期ウィンドウを再利用|
|表示中の PDF にフォーカスしたまま Ctrl+O / Ctrl+W|アプリの選択ダイアログ／現在ウィンドウの閉鎖|
|引数なしの追加起動|既存ウィンドウをアクティブ化し、空ウィンドウを増やさない|
|初期化直後に閉じる／最後の閉鎖と追加起動を繰り返す|クラッシュや要求の黙殺、残留プロセスがない|
|文書内の別 PDF／HTTP(S) リンク|別 PDF は共通管理、Web はユーザー操作時に既定ブラウザー|
|PDF を表示領域にドラッグ|表示中の文書を置き換えない|

連続起動例：

```powershell
1..10 | ForEach-Object { & $exe $a }
& $exe '.\artifacts\test-data\別フォルダー\..\論文 A #100% &.pdf'
& $exe '.\artifacts\test-data\別フォルダー\論文 A #100% &.pdf'
& $exe '.\artifacts\test-data\missing.pdf'
```

## 実施結果

2026-10-29、Windows 11 x64（OS build 26200）、WebView2 Runtime 156.0.4314.50 で配布用 self-contained バイナリを起動しました。自作の 3 ページ PDF を使い、実際の本文と標準ツールバーをスクリーンショットとアクセシビリティツリーで確認しました。

|受け入れ項目|結果|
|---|---|
|1. A を開く|成功。初期空ウィンドウと同じハンドルを PDF 用に再利用|
|2. B を別ウィンドウで開く|成功。A を維持し、B の本文を表示|
|3. A を追加起動で再度開く|成功。同じハンドルの A を前面化し、ウィンドウ数は 2 のまま|
|4. 最小化した A の再オープン|成功。復元後も 2 ページ目と変更後のズームを保持。最大化→最小化→再オープンも最大化のまま復元|
|5. 最初の A を閉じる|成功。PDF 本文にフォーカスした Ctrl+W で A だけ閉鎖、B は表示・ズーム操作可能|
|6. 最後の B を閉じる|成功。主プロセス PID の消滅を確認|
|7. 同じ PDF の連続起動|成功。既存プロセスに 10 並列要求、さらにアプリ未起動から 10 プロセス同時起動の両方で 1 主プロセス・1 A ウィンドウ。追加プロセスは終了コード 0|
|8. 日本語・空白・記号パス|成功。`論文 A #100% &.pdf` の実描画と起動元カレントディレクトリ基準の相対パスを確認|
|9. 同名別フォルダー|成功。3 つ目の独立ウィンドウで別本文を表示し、パス欄で区別|
|10. 存在しない PDF|成功。偽 PDF、正常な B と混在した要求も完了し、A/B を維持してアプリ内にエラー表示|

追加で、PDF 本文にフォーカスした `Ctrl+O` によるアプリのファイル選択ダイアログ、アプリ内での既存 A の再利用、大小文字を変えたパス、引数なしの追加プロセスの正常終了を確認しました。複数引数で新しい同名文書を開いた直後に既存 A を選択したケースでは、バックグラウンド文書の読み込みが完了しても A が前面に残りました。

検証で見つけた、送信前に切断したクライアントによるパイプの停止と、形式不正 PDF の例外が混在要求を中断する問題は修正し、それぞれ自動テストを追加しました。後者は配布バイナリでも再確認しました。

通常デスクトップと Codex のサンドボックスは Windows オブジェクト／デスクトップの境界が異なるため、追加起動の GUI 検証は通常デスクトップ側で実施しました。サンドボックスだけに起動した検証プロセスは別途終了し、アプリの多重起動検証のプロセス数には含めていません。

初版の GUI 確認後の最終変更（エラー欄の改行、異常 URI の防御、処理例外後のパイプ継続）はビルド・自動テストで確認し、初版 ZIP は `artifacts/release/` に生成しました。初版の最終変更後の GUI 再確認は未実施です。
